# Catalogue diagnostic scripts verification

Implemented on `feat/catalogue-diagnostics`, 2026-11-17, following approval of the Audiophile Impact Assessment. The existing PowerShell exporter was replaced with a registered-folder-only launcher; the Python database tool supplies shared inspection code, and the third script compares saved snapshots. Usage and before/after commands are in `tools/README.md`.

Validation: 14 Python unittest fixture tests passed. PowerShell syntax parser passed. Python command-line help passed for both Python entry points. `git diff --check` passed (Git reports the repository's normal LF-to-CRLF conversion notice for PowerShell).

Fixtures cover readonly database bytes, image blob hashes, metadata errors, raw-tag mismatch inputs, scope containment, orphan/out-of-scope tracks, missing artwork references/blobs, mismatched snapshot scopes, absent databases/roots, overlapping and disabled registered roots, real WAV ID3 picture types and image hashing/decoding, JSON sidecars, invalid images/sidecars, malformed scope rejection, protected report outputs, snapshot/comparison CLI paths, baseline comparison, an injected playback guard interruption, and native DSF DSD256 header/ID3 extraction with one-bit depth normalization.

The real local-process guard refused inspection while `cadence-core` and `cadence-engine` were running. No live catalogue/database was inspected, no engines were stopped, and no music files were modified. CLI fixture tests replace the guard only around temporary fixture data. A live successful PowerShell workflow, DFF/other format samples, NAS permissions, Linux process checks, and Windows PowerShell 5.1 remain user/environment validation items. Frontend/native application builds were not run because these standalone scripts do not modify application code.
